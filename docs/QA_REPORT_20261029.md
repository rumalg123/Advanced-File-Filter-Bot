## Search performance findings

The remote clone's representative queries used collection scans rather than an
index. Multi-token plans could exhaust the 3,000 ms explain budget; the repaired
profiler makes this visible. No indexes were added, removed or renamed.

A local copy of all 96,908 records' search fields reproduced multi-token costs:
`Spring of Youth` took about 4.4 seconds and returned 34 matches; `Dae Jo Yeong`
about 2.8 seconds / 135 matches; the synthetic miss about 3.4 seconds / no matches.
These are individual runs under capped QA resources, not p95 production latency.

Equivalent regex experiments were measured before considering a change. Dotall
and lazy variants gave little benefit. A scalar token-conjunction alternative
improved several short queries, but made the tested full-filename query slower
(about 0.28 to 0.67 seconds). It also needs a legacy array-field policy. **No
unvalidated matcher change was shipped.** PH-006 still needs a reviewed query
strategy and representative latency acceptance; unit success is not proof of
production search performance.

## Remaining release gates

- The automated suite measures 48.05% line coverage. Live checks cover more flows,
  but this pass does not prove exhaustive behavior or sustained production load.
- **PH-028 is incomplete.** Do not enable independent multi-DB ingestion: the
  defensive write block is intentional until global ownership is implemented.
- Search performance remains measurable work as described above. Exact counts
  and multi-token scans need representative SLO/throughput acceptance.
- Atlas-managed snapshot restoration, multi-replica/mixed-version recovery,
  extended queue overload, and real upstream FloodWait remain separate gates.
  Successful local restoration does not establish Atlas backup permissions or RPO.
- Optional flags remain default-off in source and the roadmap remains
  `Implemented (off)`. Test-only enablement does not authorize production rollout.
- Run the required GitHub Actions checks on the final branch before merging.
  Tracker statuses remain **In review**, because its definition of Verified also
  requires merge and independent acceptance evidence.

## Reproduce the automated gate

Use Python 3.13 and disposable localhost-only MongoDB/Redis instances with the
policies described above. Export `TEST_MONGO_URI=mongodb://127.0.0.1:27017`,
`TEST_REDIS_CACHE_URI=redis://127.0.0.1:6379/0`, and
`TEST_REDIS_STATE_URI=redis://127.0.0.1:6380/0`.

```sh
python -m pip install -e '.[dev]'
python -m pip check
python -m compileall -q bot.py config core handlers repositories scripts tests
python -m ruff check --select F821,F822,F823 .
python -m pytest --cov=core --cov=handlers --cov=repositories
sudo docker compose --profile protected-state config --quiet
sudo docker build --tag file-filter-bot:qa .
```

Run tests from a secret-free source checkout/snapshot; the application loads
`.env` at import, and conftest only overrides the required inert settings.
Never point `TEST_*` variables at existing remote services. The runtime QA
harness used local fixtures and explicit destination/recipient restrictions.
